## Engineering

- `lib/phase13PdpCopyReleaseGate.ts`: permits **two disjoint, strict modes**: (a) one OWNER-SSO-protected Vercel Preview (known Vercel project and exact `work/phase13-approved-pdp-public-read-gate-20261010` branch, no user query string can enable it); (b) `VERCEL=1`, `VERCEL_ENV=production`, exact **207 live pins + source version**, `FEYA_PUBLIC_APPROVED_PDP_COPY_RELEASE=phase13-owner-approved-pdp207-20261010-v1` and a **separate** `FEYA_PUBLIC_APPROVED_PDP_OWNER_SIGNOFF=approved-2026-10-10`. **Independent source-code lock** `PHASE13_PRODUCTION_PUBLISH_AUTHORIZED=false` is enforced even when both Vercel release flags are unexpectedly present. Production publication requires a SECOND, separately reviewed owner release PR to enable that constant. The Vercel integration returned **403 Forbidden** when attempting to LIST the project's env metadata on 10 October; no secrets were read or changed. Rather than assuming their values, this Git lock guarantees zero public effect. The Production release flags default `off` in `.env.example`. This PR has a separate authenticated **preview-only full 207** read, so the owner can visually compare real product pages before any public enablement. Unauthorized preview domains/branches receive no approved copy. The public release additionally demands `208` historical source pins, `207` eligible live pins and exactly one known owner-suppressed duplicate; this preserves the 2026-09-24 human suppression decision. Presence of the old review flags can never enable publication.
- `lib/seoPublishedPinnedPdpServer.ts`: request-memoized, **server-only service-role read** of exact current binding, exact pinned draft ID and exact active product portfolio page, all scoped by one immutable manifest URL/UUID/SHA/revision. All 4 approved original blocks projected without editing strings. `selectApprovedStorefrontCopy` validates the original approval, version timestamp and SHA. Any stale/edited/revoked/missing source returns **null** (legacy display fallback), not a different/latest/AI-generated draft or 500. No session PII, no browser API and no DB migration.
- `lib/seoApprovedStorefrontServer.ts` keeps the old protected owner-auth-only review path untouched. On independently enabled public Production release it can return a `status:'published'` and the exact approved text, otherwise the old `status:'disabled'` and legacy public PDP are unchanged. No product pricing, checkout or Search release activation can be driven from this mode.
- `app/shop/[slug]/page.tsx`: owner-approved **data-only** candidate under one versioned server route source. It reuses original `ProductDetailClient.tsx` **byte-for-byte** (the owner-frozen JSX/gallery/right/variants/CTA). When the public copy is genuinely validated, the already-existing `withOwnerApprovedComponentReview` opt-in marks a *shallow copy* of the product for the **left** physical-pieces list. No synthetic sellable option is created, and the right selector stays unchanged. The published mode does **not** flip the existing Cart CTA into preview-only mode.
- Public `generateMetadata` reads the same **request-memoized exact approved draft** for the published page's title/description when enabled, preserving existing runtime `releaseRobotsForPath`, canonical route, images, and original schema/route. Current v12 still controls all **207 PDP noindex**. No new collection, new page owner or sitemap entry.
- The historic Product OS freeze manifest records only the legitimately modified **server route** `app/shop/[slug]/page.tsx` content blob SHA; no page layout or visible JSX classes or component markup changes, no other 44 frozen surfaces rebaselined. All tests must prove the original frozen `ProductDetailClient.tsx` SHA `729514b30288a38429bad3900c025c69d452eea1` is unchanged.
- Performance: at most three scoped/current source SELECTs in parallel for a genuinely enabled PDP, memoized within the RSC request (so Metadata/Body share one source). No persistent cache of revocable approvals. This is acceptable for initial ~207 PDPs but should be measured before enabling; if 95th-percentile PDP TTFB suffers, switch to a service-only signed projection RPC in a subsequent bounded phase. Do not block guest checkout unnecessarily.
