## 1. Что изменилось в плане

Владелец намеренно отложил формованные/скульптурные пластиковые и акриловые корсеты и зеркальные пиджаки/шорты/леггинсы до отдельного этапа с данными и поддержкой товарного типа. Продолжать собирать для них размеры, крепления и цены как условие первого запуска было неверным приоритетом. Эти работы вынесены из критического пути запуска.

В текущем каталоге конкретно определены **19 отложенных ID: 17 формованных корсетов/топов и 2 зеркальных комплекта**. Полный список закреплён в owner manifest. Материал, цвет, слово corset или dress сами по себе не исключают остальные товары. Одобренные сценические изделия с пластиковыми элементами и корсеты из vegan leather остаются доступными для оценки пилота. Девять design-pair proposals также не требуется закрыть целиком: проверяются лишь затронутые выбранным выпуском товары.

Товар `40384eea-fd82-40f4-98e7-804383c42796`: владелец подтвердил бра и юбку; бра — золотая vegan leather, форма похожа на harness/bra. Материал юбки, пояс, чёрная одежда и точные размерно-цветовые цены этим ответом отдельно не подтверждены. Состав фиксируется, прежнее одобрение текста сохраняется; товар не входит в первую пятёрку и не задерживает её. Уже известный headpiece-only товар также не требует повторного вопроса.

**Dress / Jacket:** обе оси отсутствуют в `COMPONENTS` формы `app/admin/listing-master/ListingMasterPage.tsx`; этот же allowlist обрабатывает отправку формы. Поэтому наблюдение владельца имеет конкретное основание в коде. Добавление одной надписи не решит контракт типа, mapping и keyword scoring. Это отдельная согласованная задача расширения. Наличие/отсутствие метрик для физических платьев пока не доказано; названия с Dress часто принадлежат наборам top+skirt, их нельзя массово исключить.

## 2. Измеренный текущий запас работы

SELECT на текущем Supabase: 224 последних черновика, из них **208 approved** и 16 not_reviewed. Это статусы сохранённых текстов, не разрешение продаж. У 136 из 208 approved черновиков сохранённый metrics status равен validated; он не делает исторические данные свежими.

Проверяемый offline selector сопоставил 243 товара с черновиками, текущими Listing Master decisions, сигнатурой составов и точными Primary keyword IDs в сохранённом банке. **28 карточек** прошли эти предварительные условия. Остальные 196 не попали в эту строгую очередь подготовки; это не отзыв их прежних подтверждений и не утверждение о плохом качестве. 19 отдельных ID перенесены в расширение.

В выборке сохраняются исторические метрики: например, у пяти выбранных Primary дата `2026-06-29`. Дата SELECT не является новой выгрузкой Google. Период измерения, полная targeting provenance и актуальный спрос этим этапом заново не установлены. Новую выгрузку не объявляем обязательным условием работы над уже подготовленными карточками; недостающие данные запрашиваются только при решении, которое от них зависит.

Найдено **23 группы точного совпадения сохранённого Primary** среди approved drafts с одинаковым market/language scope. Это повод проверить владельца интента, не измеренная каннибализация в Google и не команда слить товары.

## 4. Конкретные разрывы перед выпуском

1. **Публичная PDP читает storefront view**, saved preview читает `agent_output_snapshot`. В текущем `app/shop/[slug]/page.tsx` нет прямой привязки к конкретному approved draft ID/hash. Следующий adapter должен передать точную утверждённую версию в уже согласованный компонент; storefront view и HTML проверяются, изменение оформления не требуется.
2. **Запросы.** Generic `futuristic armor costume` разделён несколькими PDP. Закрепить type/intent owner и более точные области товаров; не назначать владельца по порядку UUID или максимальному volume. Совпадение запросов допустимо как вторичная релевантность, accountable primary owner должен быть определён перед release.
3. **Offer и покупка.** Composition-ready не подтверждает size × color × option quote. Страница сейчас строит `Offer` с `PreOrder` при наличии цены. Перед публичным выпуском проверять фактическую возможность заказа и цену конкретного предложения; не выдавать legacy schema за утверждённое наличие.
4. **Маршруты.** Ранее выявленные collection links без route должны быть разрешены в пределах пилота: либо существующий полезный target, либо готовая collection, без массового создания страниц. Дизайн остаётся согласованным.
5. **Общие условия.** Подтверждённый public domain, company/contact/policies, защищённые admin routes, платежный сценарий и технические проверки остаются отдельными задачами. Новый Ads API доступ, обработка всех 243 карточек и GSC bulk export не являются безусловными предварительными условиями первого ограниченного выпуска.

## 5. Следующий спринт по зависимости

| Задача | Owner; вход → выход | Проверка / blocker | Rollback / done |
| --- | --- | --- | --- |
| P1 Версия контента | CQA + CPIM + Engineering; 5 draft IDs/hashes + Product Truth → reviewed field-level content/claims diff и привязка renderer | Состав/материал/варианты совпадают; CQA, source IDs, hash; отсутствие quote не исправляется текстом | Предыдущий immutable draft; done: 5 проверяемых render payloads, без новой генерации |
| P2 Владение интентом | OSPM + SCO; сохранённые keywords/23 overlap groups → scoped query-owner proposals для пилота | Intent и существующие peers/коллекции; исследовать только открытые решения | Предыдущий ownership proposal; done: нет неразрешённого primary ownership в release |
| P3 Предложения и выпуск | Commerce + TSEO + Engineering; P1/P2 + точные цены → versioned release manifest с отдельными visible/purchasable/index flags | Server quote, HTML/metadata/schema, внутренние ссылки; провал блокирует только соответствующий product/release | Manifest и feature flags OFF; done: reproducible preview без доступа к записи рабочей БД |
| P4 Company release | Owner + TSEO; существующие identity/contact/policy факты и deploy map → публичный проверяемый сайт компании | Собрать недостающее из источников, затем один предметный запрос владельцу; анонимный доступ и admin protection | Предыдущее развёртывание; done: достоверные страницы для Google review, без обещания одобрения API |
| P5 Платежи и выборочная индексация | Commerce + TSEO + Core; проверенный release → sandbox order flow, K gate и конкретный cutover plan | Реальный провайдер/политики/версия; индексация не открывается из candidate report | Checkout/index flags OFF; done: условия конкретного выпуска выполнены и разрешён cutover |

P4 можно готовить параллельно P1–P3. Отложенные семейства возвращаются по owner decision + релевантным данным и поддержке типа. Подключение API само по себе не разрешает генерацию или публикацию их страниц.
