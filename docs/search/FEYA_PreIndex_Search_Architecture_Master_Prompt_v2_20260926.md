## 3. Critical architectural corrections

### 3.1 Product DNA is not the SEO taxonomy
Product DNA generates candidate intents. It must never automatically create indexable URLs.

Pipeline:
Product DNA
→ candidate intent
→ query cluster
→ SERP validation
→ product-set/depth validation
→ differentiation
→ internal-link support
→ ownership check
→ page-type decision.

Allowed final outcomes:
- INDEXABLE_COLLECTION
- NON_INDEXABLE_FILTER
- PDP_KEYWORD
- EDITORIAL_GUIDE
- EXISTING_OWNER_UPGRADE / CONSOLIDATE
- NONE

### 3.2 Existing preview collections are not final membership authority
Any current hard-coded text-match collection logic is temporary preview scaffolding only.

Final landing membership must come from:
- stable canonical_product_id;
- Product Truth / Product DNA;
- confirmed sellable type/configuration;
- orderability;
- versioned selection rules;
- immutable membership snapshot;
- design_family_key / distinct design counting;
- explicit include/exclude reason/evidence.

Do not use title-word matching as final collection membership authority.

### 3.3 Inventory overlap is allowed; query ownership is exclusive
One product may legitimately appear in:
- a product-type collection;
- an event collection;
- a style/persona collection;
- a material/effect collection;
- related merchandising.

This is normal inventory overlap.

But one normalized query cluster + intent + market + locale + time context has exactly one primary owner.

Secondary relevance may overlap.

### 3.4 Old SEO Content Engine is an output/content contract, not the current page-eligibility authority
Keep its useful outputs:
- title;
- H1;
- meta;
- intro;
- collection SEO/helpful modules;
- related collections;
- internal links;
- target cluster;
- long-tail variants;
- product selection logic;
- image SEO;
- excluded terms;
- humanizer/CQA rules.

But supersede any old use of Google Ads “Competition” as organic SEO difficulty. Ads Competition/bids are advertising signals only and cannot be a core organic eligibility gate.

### 3.5 Competitor taxonomy is evidence, not permission
BADINKA, iHeartRaves, Rave Wonderland, Love Khaos, Burnt Soul, Coquetry, Devil Walking, Venga and others provide patterns:
- product type backbone;
- events/occasions;
- vibe/persona discovery;
- material/effect discovery;
- performance/custom service architecture;
- editorial ↔ commerce linking.

Do not copy their entire taxonomy.
Do not create a FEYA page merely because a competitor has one.

## 7. Page eligibility engine

Use the FEYA Product DNA → Search Architecture Decision Framework as the current page-decision authority.

### SERP classification
Classify organic Top-10 into:
- Collection/listing C
- PDP P
- Editorial E
- Other

Collection intent hard gate:
- C >= 0.50
OR
- C >= 0.40 and at least one collection/listing result is in Top-3.

PDP intent:
- P >= 0.50 is strong product-specific evidence.

Editorial intent:
- E >= 0.50 is strong informational evidence.

### SERP overlap
Use normalized Top-10 overlap for neighboring query clusters:
- O10 >= 0.50 → same intent cluster by default; separate SEO owners prohibited.
- 0.30 <= O10 < 0.50 → review/merge-vs-split using SERP type + product overlap.
- O10 < 0.30 → potentially distinct intents.
- unstable SERP → HOLD and repeat later; do not publish based on one unstable snapshot.

### Collection hard gates
A candidate indexable collection requires all:
- Commercial SERP gate passed;
- Demand Score D >= 40;
- Effective Product Depth EPD >= 4;
- >= 3 distinct design families;
- Differentiation Score X >= 50;
- Internal Link Support L >= 40;
- no ownership/cannibalization veto;
- final Landing Eligibility Score >= 70.

Important: these numeric values are **versioned FEYA v1 operational policy**, not universal Google rules. Store them in policy/config/evidence, not as timeless truth.

Cold-start rule:
- lack of GA4/GSC data on a brand-new page is not negative evidence;
- use neutral business score where the framework specifies it;
- use GKP + SERP + catalog + ownership + differentiation pre-launch.

Final outcome must be one of:
- INDEXABLE_COLLECTION
- HOLD/FILTER
- PDP_KEYWORD
- EDITORIAL_GUIDE
- EXISTING_OWNER_UPGRADE
- NONE

Store machine-readable reason codes such as:
LOW_DEMAND
THIN_PRODUCT_DEPTH
EDITORIAL_SERP_DOMINANT
PDP_SERP_DOMINANT
HIGH_PRODUCT_OVERLAP
EXISTING_OWNER_STRONG
