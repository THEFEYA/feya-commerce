# FEYA — независимые допуски сайта, покупок и поиска

Дата: 24 сентября 2026. Статус: архитектурное уточнение к `FEYA_Search_Architecture_v1.md`; не разрешает публикацию или изменение production. Источники: текущие Product/Growth ветки, сохранённые owner decisions, семь приложенных исследований, `Inventory_Reconciliation_20260924.md` и `Purchase_Binding_20260924.md`.

## Исправление в плане запуска

Один общий pre-index gate полезен для **открытия коммерческих URL в поиске**, но его нельзя превращать в условие существования публичной страницы компании или демонстрации внутреннего приложения при рассмотрении Google Ads API. Проверка приложения, приём оплаты и индексация — разные события. Ни один из них не гарантирует одобрения другого. Доступ Google Ads API определяется разработческим токеном и разрешёнными возможностями; сайт служит достоверным представлением компании и назначения приложения, а не доказательством полученного доступа.

| Трек | Минимальный результат | Обязательная проверка | Что остаётся закрытым |
| --- | --- | --- | --- |
| Company / API review | На согласованном домене доступна правдивая главная, о компании, контакты, опубликованные и утверждённые условия; внутренний analytics app описан без заявления о несуществующих данных или разрешениях | Домен, публичные ссылки/HTTPS, настоящее юридическое/контактное лицо и утверждённые условия; приватные admin routes недоступны анониму; содержание соответствует заявке | Необоснованные коммерческие обещания, админка и сырые данные; SEO индексирование можно решать отдельно |
| Catalog preview | Реальные фотографии и описания подтверждённых товаров, публичные цены только если их текущая область применения известна | Product Truth, ID, состав/варианты, корректная цена или честное отсутствие точной цены; заказ и оплаты выключены там, где quote не доказан | 21 held product и все неподтверждённые комбинации не становятся покупаемыми или индексируемыми автоматически |
| Commerce activation | Серверное подтверждение точной конфигурации, размера, цвета, цены, валюты, наличия и доставки; реальный checkout и события оплаты | Заказ в sandbox/staging от выбора до завершения и отмены/возврата по утверждённой политике, проверки race/retry/ошибки и налоговой/платёжной информации | GA4 `purchase`/revenue до подтверждённой оплаты не выдаются за факт |
| Selective search launch | Только выбранные URL с собственным интентом, владельцем запроса, достаточным подтверждённым ассортиментом и уникальной ценностью | Полный K01–K18 на конкретном release, согласованная политика, canonical host, schema/crawl/sitemap и реальные проверки готовности предложения | Неиндексируемые фильтры, дубли, страницы с неизвестной ценой или составом, массовая генерация |

Это проектная декомпозиция, **не утверждение**, что Google требует оплаты или индексации для одобрения developer token. Конкретное содержание заявки и её текущий статус нужно сопоставить с её настоящим запросом, когда это станет действием.

## Две системы и источник истины

Проверенные исходники находятся в `THEFEYA/feya-commerce`: `owner-ui-v1` для Company/Growth, `work/resume-listing-batches-20260915` для Product/generation, интеграционная ветка PR #26 для выборочного переноса. Ранний канон хранится также в `THEFEYA/FEYA`; это исторический источник документов, а не доказательство второй текущей production базы. Не считать два Vercel preview URL независимыми продуктами или подтверждением двух живых БД без проверки конфигураций deployments.

Product OS владеет физическим составом, конфигурацией, размером, ценой и подтверждённым SEO draft. Growth OS владеет запросом/интентом, ownership страницы, измерением и предложением изменений. Общий Core фиксирует immutable IDs, версии, evidence, approval и execution. Сайту доступны только опубликованные версии через серверный read contract. Изменение SEO текста не меняет Product Truth; изменение цены не переутверждает SEO страницу. Контракты связываются ID и версией, не совпадением названий опций или image URL.

## Решения по найденным рискам

1. **Оставить:** индексируемый URL только после intent, inventory, ownership, content и technical checks. Предложенные численные пороги исследований являются гипотезами, а не правилом Google.
2. **Исправить:** различать company/API review, catalog preview, real commerce и search launch. Полный SEO gate не должен блокировать правдивую страницу компании. Если каталог показан без покупки, интерфейс и structured data не обещают оформляемый товар там, где покупка недоступна.
3. **Оставить hold:** 21 карточка, 142 price rows, 13 диапазонов и 113 скрытых повторяющимся `Option` строк не дают оснований для автопокупки. Offline compiler — evidence, не quote service.
4. **Не считать семь исследований каноном:** конкурентные паттерны наблюдаемы, но трафик и конверсии конкурентов не доказаны; volume/competition Ads не равны сложности SEO; поисковая частотность и доход FEYA не придумываются.
5. **Развести два статуса продукта:** `visible_catalog` и `purchasable` отдельно от `index_eligible`. Индексирование политики/служебной страницы не означает разрешения индексировать каждый товар. Разрешение Ads API не означает разрешения на запуск платных объявлений или подтверждения Merchant Center.

## Следующая исполнимая очередь

| ID / owner | Вход → выход | Доказательство готовности | Откат |
| --- | --- | --- | --- |
| LT1 / Engineering + TSEO | Сравнить фактические репозитории, ветки, Vercel projects и Supabase refs без записи → versioned deployment map | Для каждого preview и будущего домена известны commit, environment, база, index flag; визуальные контракты сохранены | Отменить лишь карту/конфигурацию, не трогать Product Truth |
| LT2 / CPIM | Девять design-review pairs и 21 held product → review packet физических моделей с source lineage; категории `same`, `different`, `unknown` | Не объединять по фотографиям и не заявлять distinct inventory без доказательств; неизвестные факты адресовать владельцу по конкретному товару | Вернуть proposal в `unknown`, UUID/историю сохранить |
| LT3 / Owner + Commerce | Действующие бизнес-условия и платежный маршрут → утверждённый публичный copy и checkout decision | Terms/returns/shipping согласованы между страницей, checkout и админкой; тестовая оплата и возврат лишь после выбора провайдера | Держать checkout выключенным и снять спорный публичный текст |
| LT4 / TSEO + Product + CQA | Текущие пять briefs, подтверждённые inventory/intent и версии контента → первый ограниченный release manifest | Нулевые query-owner конфликты, PDP source facts, crawlable links, canonical, robots/schema/sitemap и browser test на точном release | Предыдущий manifest, selective noindex |
| LT5 / GDAE + GMEL | GA4/GSC/Ads фактический доступ, event contract → проверенные события и отчёт по покрытиям | Тестовый `view_item`/checkout, реальные purchase только от completed payment; Ads permission проверяется отдельным capability call | Отключить события/импорт по feature flag, историю не переписывать |

Приоритет: LT1 и независимая LT2; LT3 до коммерческой активации; LT4 только после товарных оснований; LT5 не задерживает создание качественных страниц. До подтверждения release нет изменения индексации, дизайна, цен или production DB.
