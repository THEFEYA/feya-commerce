# Operating the guest withdrawal service

The buyer opens the public returns page, reviews the declaration and confirms it. The site records the name, contract identifier or description, chosen acknowledgement email, declaration, database timestamp and receipt reference together. Both the studio case and the acknowledgement job exist when the public API returns a receipt. Payment records and refund decisions follow their existing processes.

The intended legal benchmark is a timely acknowledgement on a durable medium giving the statement's contents and its submission date and time. A website receipt, a downloaded copy and the private delivery status do not prove arrival in the buyer's mailbox. [Directive (EU) 2023/2673, Article 11a](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX:32023L2673)

## Installation and activation

1. Under the studio's existing `manager.feya@gmail.com` account, prepare a private standalone Apps Script with `scripts/withdrawal-gmail/Code.gs` and `appsscript.json`. The mailbox owner runs `authorizeStudioMail` and grants the listed permissions. This verifies the studio identity and prints only the public OAuth audience. Pairing may be completed while the website is still in draft. It uses no mailbox, timer or website endpoint.
2. The operator deploys the reviewed routes and migration with `FEYA_WITHDRAWAL_LIVE=false` and sets `FEYA_WITHDRAWAL_GOOGLE_AUDIENCE` to the public audience above. After the canonical endpoint is ready and paired, run `installWithdrawalWorker` in the same authorized private project under the studio account. This installs a single five-minute timer using the existing grant. Database credentials stay on the server. [Apps Script identity](https://developers.google.com/apps-script/reference/script/script-app#getidentitytoken), [MailApp](https://developers.google.com/apps-script/reference/mail/mail-app), [installable triggers](https://developers.google.com/apps-script/guides/triggers/installable)
3. Before opening intake, verify two successive timer polls against the paired endpoint using the restricted `select public.feya_withdrawal_health_v1()`. It reports the actual poll time, Google quota and the oldest outstanding acknowledgement. In an isolated staging environment, use the identical migration, two controlled mailboxes, an authorized worker pinned to the staging origin and a clearly labelled synthetic notice. Verify the message by opening the independent recipient inbox and checking the declaration, entered name, contract details, chosen address, UTC time and receipt reference. Also verify a lost number and an alternative address, recipient verification, a mail outage, a missed report and the studio's private case handling. Keep test statements out of the production contract register.
4. The responsible studio operator must have restricted access to the queue, be assigned to respond promptly, and know how to check bounced or undelivered Gmail notices, handle a recipient who wrote from another mailbox, and make customer contact through the existing support channel. Agree a legal record-retention period and deletion procedure for real notices. This migration has no automatic deletion of completed notices. Record the controlled inbox evidence and who monitors the queue, then enable the feature and check its public and guest entry points with the first genuine case.
5. To pause admission, set `FEYA_WITHDRAWAL_LIVE=false`. Continue to run the worker and clear already accepted cases. Before rotating the script project, pin its new public audience explicitly. Removing the timer or audience stops delivery and requires active handling of all outstanding cases.

## Delivery and capacity

MailApp exposes a remaining daily recipient allowance and returns no message ID from `sendEmail`. `submitted` means the call returned without an exception or the studio later confirmed submission. Only an observed inbox receipt proves the specific test delivery. The script stores only the job ID, attempt ID and outcome when a report must be retried. The database grants the message content to one dispatch attempt. An inconclusive result enters private review. The stable receipt reference also appears in the message subject. [MailApp method reference](https://developers.google.com/apps-script/reference/mail/mail-app)

Consumer Apps Script currently allows 100 recipients per day across the account's use. Each run checks Google's actual remaining quota. This application caps its own grants at 90 per rolling 24 hours, gives customer receipts priority, and caps studio email alerts at ten in that window. The last twenty available Google recipient slots are reserved for customer receipts. All cases remain in the studio queue even after the email alert limit. Quota exhaustion, delayed triggers or sustained traffic can delay durable acknowledgements. The operator must monitor case ages and unresolved receipts independently of email alerts. [Google quotas](https://developers.google.com/apps-script/guides/services/quotas)

## Private case handling

Use the restricted Supabase SQL console, or a server-side operator with the equivalent access. Browser roles have no table or RPC privileges. The Google worker can take one ready message or report one attempt. It cannot look up orders, read the case register, send arbitrary messages or decide a refund.

- List outstanding cases with `select * from public.feya_withdrawal_open_cases_v1(100)`. The list contains references, timestamps, recipient-verification need and job states. Use `feya_withdrawal_case_v1(reference)` only on the individual case under review.
- A paid customer's order number, checkout name and original mailbox can authorize a confirmation for that mailbox. The customer may supply an alternative contract description or email. The notice is accepted immediately and the studio must verify control of the submitted mailbox and the case promptly before sending the statement there. Record the restricted evidence reference with `feya_withdrawal_verify_recipient_v1(reference, verified_email, actor, evidence_reference)`. A failed match cannot replace the declaration's original address. No email token is required to file. An optional checkout token never authorizes an unrelated recipient.
- When a send/report is interrupted, the taken job cannot automatically be sent again. After 15 minutes the next worker poll flags it for review. Check the precise attempt ID and receipt with the sender and recipient through an established channel. If independent evidence confirms a handoff, record `feya_withdrawal_reconcile_job_v1(job, attempt, 'confirmed_submitted', actor, evidence_reference)`. Release the same message for another attempt only with positive evidence the earlier one was not sent. The function requires the exact attempt and imposes at least one hour before a `confirmed_not_sent` replay. An empty Sent search or absent read receipt is insufficient.
- For a bounce after a reported handoff, use the case reference, contact the verified customer promptly via the established channel and document the resolution with support. The worker does not read Gmail. Monitor both the mailbox and cases until handled. Mark the studio action complete using `feya_withdrawal_resolve_case_v1(reference, actor)` after fulfilling the request through the proper process.

The raw IP and optional checkout token are absent from the case data. The service keeps bounded hourly counts using hashes for IP and mailbox quotas; inactive buckets age out on new intake after 48 hours. Keep personal data and Google identity tokens out of URLs, monitoring payloads, case exports and support diagnostics.
