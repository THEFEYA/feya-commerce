## Actual preview implementation

1. **`lib/commerceOwnerCartReview.ts`**: strict, read-only parser of the existing `feya_visual_cart_v1` browser localStorage set by existing frozen `ProductDetailClient.tsx`. Extracts immutable canonical product UUID from the existing cart item ID, validates slug, price currency EUR, quantity, configuration UUID where present and display fields. Drops invalid/stale rows instead of trusting malicious localStorage, and never performs any network or database write.
2. Pure integer-cent *illustrative* totals: selected client-side display line prices × quantity, owner €19/€35 delivery, exact €500×max(0,distinct canonical product IDs−1) packing fee; fee row rendered **only** for 2+ distinct product listings. Tax/amount_due/remote verified carrier cost return NULL/not_verified, pay/order/provider remain strictly FALSE. This is **not a payment quote**. Existing current authoritative server quote/money/offer storage is not bypassed. Before first payment the server must revalidate exact currently priced variant + owner policy + approved outbound destination + tax + Seller Online amount/session/webhook.
3. **`components/CartOwnerLiveReviewClient.tsx`**: actual item selection from the same preview origin's real product pages, selected size/color/configuration, images, unit prices shown as **unverified preview only**, reactive quantity+remove controls, one sensible comment field, Standard vs Express vector icons, intuitive purchase summary, remote surcharge explicitly pending verification, no false payable total or provider logos.
4. Address form is **pure client memory only** and is never submitted, transmitted, emailed, tracked, persisted to localStorage, database or services. Country select shows the ISO dropdown as a *visual example*, **not a live served-country claim**. Globally blocked countries and Ukraine excluded. States/provinces shown as dropdown ONLY for **US, Canada, Australia** (with complete label choices); other countries don't get a useless State field. Customer can enter first and last name, email, phone for courier, country, state if applicable, city, ZIP/postcode, street, optional apartment and one optional order note. No buyer package geometry question.
5. Required terms/returns/shipping acknowledgment UI and legally necessary privacy notice are separate from an independently **unchecked optional** marketing/newsletter checkbox. None creates a contract until actual checkout; no data collection/event on click. The payment button is disabled and clearly labeled `Checkout not active`. Receipts/invoice and legitimate provider-supported card/bank/PayPal options are for AFTER real Seller Online onboarding, not mocked or guaranteed.
6. **`app/cart/page.tsx`**: only when `VERCEL=1`, `VERCEL_ENV=preview`, exact Vercel project and **`work/m2-real-bag-owner-preview-20261010`** Git branch (plus Deployment Protection) does the route show the new client. Therefore `Add to bag` / `Buy it now` from a product on THIS preview branch works normally and navigates the real `/cart` path with this visual/functional review. On ALL other branches and Production the original **Online checkout is not active yet** safe placeholder still renders. `/cart` retains noindex.
7. The original frozen `components/ProductDetailClient.tsx`, product offers/options/prices/media and the 18 Search v12 indexed owners remain unchanged; no other public visuals edited. Feature flag cannot be enabled by any browser query/header.
